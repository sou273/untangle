# Untangle — 提出用の説明文（下書き）

> 第5回 Agentic AI Hackathon with Google Cloud 提出用。【】の箇所は、開発者の店で通しで使った実数が出たら入れる。

## ひとことで

**スタッフが過去に送ったメールを読み込ませるだけで、店の判断を全部取り出し、決裁者が確かめて決まりにすれば、その業務を譲渡できる。**

小さな店の判断は、決裁者の頭の中と、スタッフが送ったメールの中にしかない。Untangle は送ったメールのひな形から外れた文、つまりスタッフがその場で判断して書き足した文を全部取り出し、判断ごとのテーマに分ける。決裁者は4つの段を進めるだけで、テーマごとに決まりとマニュアルができ、全部が完了すると「業務を譲渡できます」と表示される。

## ユーザー像

- 個人店・零細企業の決裁者（店主・社長・マネージャー）。IT担当はいない
- その店でお客様にメールを返しているスタッフ（アルバイト・パート・事務員）

開発者自身が、切子体験工房の二代目マネージャーとしてこの立場にいる。予約の確定や調整のメールを、毎日スタッフが送っている。

## 課題

- **判断は、決めた人の頭の中にしか無い。** スタッフは同じことを何度も聞きに来て、決裁者が不在だと止まる。人が入れ替わると判断の基準ごと消える（事業承継でも同じ）
- **実際には、スタッフがそれぞれの判断で答えている。** 切子体験工房で団体予約の記録160件を見直すと、学校団体の約4割で、生徒が大人として登録されていた。同じ条件で判断が割れていたのに、決裁者自身も気づいていなかった
- **手順書を書こうにも、何を書けばよいか分からない。** 決裁者に「判断を全部書き出してください」と頼んでも、思い出せるのは一部だけ
- **AIに任せようにも、どこまで任せてよいかの根拠が無い。** 「優秀なAIになんとなく任せる」と、誤りに誰も気づけない

## なぜ「送ったメール」なのか

判断の跡がいちばん確かに残っているのは、スタッフがお客様に実際に送った返事だ。決裁者とスタッフの相談は口頭で消えるが、送った返事は消えない。

小さな店の返事の多くはひな形どおりで、スタッフが判断した箇所だけがひな形から外れる。例えば「12名を下回る減員は、2週間前から人数分のキャンセル料を頂戴します」「ロゴ入れは当日はお受けできません」のような一文だ。外れた文を集めれば、その店の判断が一覧になる。過去のメールを全部読めば、判断のテーマは読み込んだ時点で全部出そろう。

## ソリューション

### 決裁者がやること（4つの段）

1. **分け方を確かめる**: Untangle が分けたテーマごとに、実例のメールを見て「同じ判断のまとまりになっているか」を確かめる。違うものは外したり、ほかのテーマと一緒にしたりする
2. **決め方を選ぶ**: 実例に出てきたスタッフの答え方が選択肢として並ぶので、1つ選ぶ（自分で書いてもよい）。いま決めないものは「あとで決める」に残せる
3. **違う答え方を片付ける**: 選んだ決まりを過去の実例に当て直すと、決まりと違う答え方をしていた返事が出てくる。1通ずつ「これからは決まりどおり（スタッフに伝える）」か「この場合は例外（条件を一言）」に片付ける
4. **完了**: そのテーマのスタッフ向けマニュアルができる。スタッフへの知らせもコピーして、いつもの連絡に貼れる

ダッシュボードの一番上に「譲渡まで　8テーマ中3完了」のような帯があり、全部のテーマが完了すると「✓ 業務を譲渡できます」に変わる。そこで、全テーマのマニュアルを1つにまとめて渡せる。

### 裏で起きていること

1. **ひな形からの外れを取り出す（ブラウザの中）**: Gmail から送ったメールを読み取り専用で読み、何通にも出てくる行をひな形として外す。自動送信のメールと、お礼・承知だけの返事も外す
2. **名前や番号を伏せる（ブラウザの中・AIを使わない）**
   - 電話・メール・住所・宛名・会社名の語尾は、決まった規則で伏せる
   - 署名から集めたスタッフ名は「スタッフA」に置き換える
   - 日本語の辞書（kuromoji）で、固有名詞と辞書に無い語を伏せる。ページが固まらないように、裏の Web Worker で動かす
   - 「様」の前は、名前でないと分かる語以外すべて伏せる
   - 伏せ残りの疑いがある行は、送らない
3. **もう一度検査する（サーバー）**: 届いた文を決まった規則で伏せ直し、1字でも変われば Gemini に渡さない。受け取った文は保存しない
4. **テーマに分ける・決めることを並べる（Gemini）**: 伏せた後の文だけを Gemini 3.5 Flash に渡し、判断ごとのテーマに分けさせる。さらに実例の答え方を選択肢にして、どの実例がどの答えかを付けさせる
5. **当て直して数える（決まったプログラム）**: 決裁者が選んだ答えを条文にし、過去の実例に当て直して、違う答え方を数える。違いが片付けば完了とし、規程の版を出す
6. **巡回エージェント（ADK）**: ダッシュボードを開くたびに巡回する。テーマの状態を読み、譲渡までに決裁者がやることを洗い出し、テーマごとに次の一手のメモを書く（例:「13名・14名を受けるかで答え方が分かれています。どこまで受けるかを選んでください」）。最後に「完了3／8テーマ、まずは◯◯から」と報告する

## 「固く渡す」— 自律性とガバナンスの両立

このハッカソンのテーマ「作れる」から「使える」へに対して、Untangle が出す答えはこうだ。AI に判断を任せるのではなく、**AI には判断を見つけさせ、決めるのは決裁者、合っているかを数えるのは決まったプログラム**にする。

| 層 | 何を固くしているか |
|---|---|
| データ | 生のメールはブラウザの外に出さない。伏せるのは AI ではなく規則と辞書。伏せ残りの疑いがある行は送らず、サーバーでも検査し直す。決裁者が確かめる手間は無い |
| 判断 | 決まりの答えは、スタッフが実際に答えた選択肢から決裁者が選ぶか、自分で書く。AI が決まりを作ることは無い |
| 権限 | エージェントに渡す道具は「状態を読む・やることを洗い出す・メモを書く」の3つだけ。決まりを確定・変更する道具も、片付ける道具も持たせていない（テストで固定） |
| 合否 | 決まりと違う答え方を数えるのも、完了の判定も、決まったプログラム。AI に合否を言わせない |
| 網羅 | 過去のメールを全部読むので、決まりと違う答え方が残ったまま業務を渡すことは無い |
| 可観測性 | エージェントが呼んだ道具とその結果を、すべて画面に出す |
| 費用 | AI の受け口に、接続元ごと・全体の回数制限をかける。Gemini には用途ごとに考える量（思考トークン）の上限を付ける |

## 実際に使ってみて

- 開発者の店で実際に送ったメール【◯通】を読み込み、【◯テーマ】に分かれた。【◯テーマを完了】
- 伏せ方は、実際に送ったメールで点検しながら規則を足した。最後の点検で残っていたのは英字の名前1件だけで、これも規則に加えた
- 【決まりを作ったことで分かったこと（例: 同じ問い合わせに、スタッフで答えが違っていたテーマ）】

## 審査用のデモ

公開URLを開くと、架空の切子体験工房が送ったメール98通を読み込み、途中まで進んだ状態から始まる（実在のお客様とは関係ない）。

- 8テーマのうち、3つは完了済み。ほかは「分け方を確かめる」「決め方を選ぶ」「違う答え方の片付け」「あとで決める」のどれか
- 「完了した3テーマのマニュアルを見る」で、譲渡するときに渡すマニュアルを見られる
- カードを押すと、そのテーマで次にやることが一番上に出る
- ログインは要らない。自分の Gmail で試すときだけ、URL の末尾に `?real=1` を付けてログインする

## 使っている Google Cloud

| 用途 | プロダクト |
|---|---|
| 画面・API・エージェント | **Cloud Run**（東京リージョン。専用のサービスアカウントには Vertex AI の利用権限だけ） |
| テーマに分ける・決めることを並べる・巡回エージェントのモデル | **Gemini API**（Vertex AI、gemini-3.5-flash、東京リージョン） |
| 巡回エージェント | **Agent Development Kit (ADK)** |
| 送ったメールの読み取り | **Gmail API**（読み取り専用。読むのはブラウザの中だけ） |
| ビルドとイメージ | Cloud Build / Artifact Registry |

## これから

- 店で使っている返信の手段（LINE・Googleフォームの自動返信など）からも、ひな形からの外れを読む
- 完了したテーマのマニュアルを、Googleドキュメントへ書き出す
- マニュアルを AI への指示として渡す前に、過去の実例を AI に解かせて合格したものだけを渡す
- 体験工房以外の業態（飲食・小売・士業の事務所）で試す
